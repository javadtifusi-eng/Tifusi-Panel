# نصب

## پیش‌نیازها

### مشخصات سرور

| نقش | حداقل | پیشنهادی |
| --- | --- | --- |
| پنل | ۱ هسته‌ی CPU، ۱ گیگابایت رم، ۱۰ گیگابایت دیسک | ۲ هسته‌ی CPU، ۲ گیگابایت رم، ۲۰ گیگابایت دیسک |
| نود | ۱ هسته‌ی CPU، ۵۱۲ مگابایت رم، ۱۰ گیگابایت دیسک | ۱ هسته‌ی CPU، ۱ گیگابایت رم، ۲۰ گیگابایت دیسک |
| پنل و نود روی یک سرور | ۱ هسته‌ی CPU، ۲ گیگابایت رم، ۱۵ گیگابایت دیسک | ۲ هسته‌ی CPU، ۲ گیگابایت رم، ۲۵ گیگابایت دیسک |
| پنل، نسخه‌ی حرفه‌ای (MySQL) | ۲ هسته‌ی CPU، ۲ گیگابایت رم، ۲۰ گیگابایت دیسک | ۲ هسته‌ی CPU، ۴ گیگابایت رم، ۴۰ گیگابایت دیسک |

اندازه‌گیری روی یک نصب در حال کار: کانتینر پنل حدود ۱۰۰ مگابایت رم، داشبورد حدود ۶ مگابایت و نود حدود ۵۰ مگابایت مصرف می‌کند و ایمیج‌ها حدود ۱ گیگابایت از دیسک را می‌گیرند. دیسک بزرگ‌تر پیشنهادی برای به‌روزرسانی ایمیج‌ها، لاگ‌ها و بکاپ‌هاست. نیاز CPU و پهنای باند نود را حجم ترافیک تعیین می‌کند، نه تعداد کاربران.

### سیستم‌عامل و معماری

- سیستم‌عامل: Ubuntu 22.04/24.04 یا Debian 11/12 (نصب‌کننده‌ها از `apt-get` استفاده می‌کنند). توزیع‌های دیگر لینوکس با نصب دستی Docker کار می‌کنند.
- معماری: x86_64 (amd64). نصب‌کننده روی معماری دیگر پیش از تغییر سیستم متوقف می‌شود؛ ساخت محلی از سورس خصوصی در نصب عمومی وجود ندارد.
- دسترسی root و نشانی IPv4 عمومی.

### شبکه

- پنل: برای TLS داشتن رکورد DNS متصل به سرور توصیه می‌شود. برای گرفتن گواهی رایگان Let's Encrypt پورت ۸۰ باید در دسترس باشد.
- نود: IKEv2 به پورت‌های UDP 500 و 4500 نیاز دارد؛ L2TP علاوه بر آن به UDP 1701 و ماژول‌های کرنل `l2tp_ppp` و `ppp_generic` روی میزبان نیاز دارد.
- نصب عمومی به گیت‌هاب و ghcr.io دسترسی می‌خواهد؛ سورس خصوصی روی سرور کاربر بیلد نمی‌شود.

## پنل — نسخه‌ی عادی (SQLite)

</div>

```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/javadtifusi-eng/Tifusi-Panel/main/install.sh)"
```

<div dir="rtl">

نصب‌کننده Docker را آماده می‌کند، مخزن را clone می‌کند، `TIFUSI_SECRET_KEY` را تولید می‌کند، در صورت تمایل برای دامنه‌ای که به سرور اشاره می‌کند گواهی Let's Encrypt صادر می‌کند و مجموعه را با Docker Compose راه‌اندازی می‌کند. فرمان مدیریتی `tifusi panel` نیز نصب می‌شود.

## پنل — نسخه‌ی حرفه‌ای (MySQL)

</div>

```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/javadtifusi-eng/Tifusi-Panel/main/install.sh)" -- --pro
```

<div dir="rtl">

همان پنل، با این تفاوت که همه‌ی اطلاعات (کاربران، نودها، هاست‌ها، گروه‌ها، هسته‌ها و تنظیمات) به‌جای فایل SQLite داخلی در یک کانتینر MySQL 8.4 نگهداری می‌شود. نصب‌کننده رمزهای MySQL را خودکار می‌سازد، MySQL فقط از شبکه‌ی داخلی Docker در دسترس است و داده‌هایش در پوشه‌ی `mysql-data/` ذخیره می‌شود. برای تعداد کاربر زیاد، یا هنگامی که پایگاه‌داده‌ای استاندارد برای مدیریت و پشتیبان‌گیری لازم است، این نسخه را انتخاب کنید؛ `tifusi panel backup` و `tifusi panel restore` خروجی MySQL را هم شامل می‌شوند. نصب نود برای هر دو نسخه یکسان است.

## راه‌اندازی اولیه

۱. داشبورد را باز کنید. هنگامی که هیچ مدیری وجود ندارد، صفحه‌ی ورود روال راه‌اندازی را ارائه می‌کند.

۲. روی سرور پنل یک کلید راه‌اندازی یک‌بارمصرف تولید کنید (گزینه‌ی `tifusi panel key` در منوی مدیریت هم همین کار را انجام می‌دهد):

</div>

```bash
docker exec -it tifusi-panel tifusi-cli generate-admin-key
```

<div dir="rtl">

۳. کلید را وارد کرده و نام کاربری و رمز حساب مالک را تعیین کنید.

## نصب اختیاری نود روی سرور پنل

نصب‌کننده می‌پرسد **نود روی همین سرور نصب شود؟ [y/N]**. پاسخ پیش‌فرض **نه** است: فقط پنل نصب می‌شود. بعداً در **نودها ← نود جدید** آی‌پی سرور دیگری را وارد و عاملش را با SSH یا دستور ارائه‌شده نصب کنید. لازم نیست سرور پنل خودش نود VPN باشد.

با **بله**، پس از آماده‌شدن پنل یک نود محلی نصب و ثبت می‌شود؛ آدرس و پورت عامل قابل انتخاب‌اند. کانتینر `tifusi-node` ازقبل‌موجود دست‌نخورده می‌ماند. بعد از ساخت مالک، در **هسته‌ها** یک هسته Xray یا IKEv2 انتخاب و نود را به آن متصل کنید؛ نصب‌کننده خودکار هسته یا مشتری نمی‌سازد.

چک‌لیست داشبورد ثبت نود، همگام‌سازی موفق، اتصال هسته، هاست و اولین کاربر را نشان می‌دهد. آماده‌بودن تنظیمات جای اتصال واقعی گوشی را نمی‌گیرد. API بیرونی از آدرس داشبورد به‌اضافه `/api` قابل دسترس است؛ پورت مستقیم backend فقط روی localhost گوش می‌دهد.
